🚀 OfferFlow HR — Short & Easy Interview Prep Guide

This guide is made for you to quickly read, understand, and explain the project in an interview. Everything is written in simple, easy-to-understand language.

💡 1. What is this project? (Simple Overview)

OfferFlow HR is a bulk offer letter generator tool. It helps HR teams send hundreds of personalized offer letters to candidates in one go.

  • Upload: HR uploads a CSV list of candidates.
  • Review: HR reviews, edits, and selects candidates in a spreadsheet grid.
  • Template: HR writes a letter template using drag-and-drop variables (like {{Name}}, {{Role}}).
  • Send & Track: The app sends emails to all candidates and tracks in real-time when each candidate opens their mail.

🎨 3. Dark Mode (How it works & code locations)

Concept: Swaps theme variables dynamically without page re-renders.

  • We store a theme state ('light' or 'dark') in React Context. When toggled, we add/remove the .dark-mode class from the <body> element and save the preference in localStorage.
  • In CSS, we define color tokens (e.g. --bg-app, --bg-card, --text-main) under body and override them under body.dark-mode. The browser swaps colors instantly.
  • Code locations: React logic is in AppContext.jsx, Toggle button is in Header.jsx, and variables are in index.css.

⚡ 4. New Added Features (How they work & code locations)

A. Real-Time Email Open Tracking (Server-Sent Events)

What it does: Changes status to "Opened" instantly when Gmail is opened.

  • We place an invisible 1x1 image (pixel) at the top of the email body.
  • Opening the email triggers a request for this image from our backend.
  • The backend updates candidate status to "Opened" and broadcasts it to the frontend via a live stream connection (SSE / EventSource).
  • Fallback: If the live stream drops, the frontend polls the database every 3 seconds with a cache-busting query (?t=Date.now()).
  • Code locations: Backend router & SSE: email.js (/track/events and /track/:candidateId.gif). Frontend connection: HistoryTab.jsx (lines 44-62).

B. Gmail-Safe Pixel Injection (Anti-Clipping)

What it does: Fixes the issue where Gmail blocked tracking pixels.

How it works: Gmail clips emails over 102KB (which happens when company logos are embedded as large SVG/base64 strings). If the tracking pixel is at the bottom of the email, Gmail will clip it, and the pixel won't load. We fix this by injecting the pixel immediately after the opening <body> tag at the very top of the email body.

Code location: Injection logic is in email.js.

C. Live Selected Candidate Template Preview

What it does: In Step 3 (Template Editor), the live preview panel on the right displays the exact details (Name, Salary, Role, Date) of the candidate you checked/selected in Step 2.

Code location: Selected candidate lookup in TemplateEditor.jsx.

💬 5. Quick Interview Answers

Q: Why use Server-Sent Events (SSE) instead of standard WebSockets?
A: SSE is much simpler and runs over standard HTTP/2, requiring no extra libraries (like Socket.io). It is extremely lightweight for unidirectional real-time updates (server pushing open status updates to client).

Q: Why do you parse CSV on the client side?
A: Using PapaParse on the frontend offloads computing work from the backend server and allows the browser to validate columns instantly before saving data to MongoDB.

Q: Why use a 1x1 transparent GIF instead of other formats like PNG?
A: GIFs are the smallest image files possible (only 43 bytes). They are supported by 100% of email clients and don't cause any visual alignment issues.
