🚀 OnboardGo — Real-Time Candidate Tracking Guide

A detailed breakdown and technical roadmap explaining the logic, database layers, and workflow behind the real-time open and acceptance tracking architecture.

📊 Tracking Workflow Flowchart

🏁 Detailed Phase-by-Phase Roadmap

Phase 1: Campaign Dispatch & DB Initialize Sent Status
When the HR manager clicks send, the backend registers candidates inside the database. It constructs an HTML email template inserting:
  • Gmail-Safe Image Pixel: Placed at the very top of the body (Line 840) to load instantly without getting blocked by Gmail's 102KB clipping rules.
  • Polished CTA Link: Inside the footer to access the unique, secure Candidate Portal.
Phase 2: Open Action Detection (Dual-Trigger) Opened Status
Status is logged as Opened under two safe conditions:
  • Pixel Hit: When the mail client loads the HTML body and calls GET /api/email/track/:candidateId.
  • Portal Fallback Hit: If image loading is disabled, opening the portal URL triggers a frontend fetch to the track API, ensuring status is resolved regardless.
// MongoDB candidate status & timestamp write on email open: candidate.status = 'Opened'; candidate.openedAt = new Date(); await candidate.save();
Phase 3: Digital Acceptance & Audit Log creation Accepted Status
When the candidate clicks "Accept Job Offer" on the web portal:
  • Updates the Candidate database status to Accepted.
  • Creates a permanent record in the History database collection to log the timestamp and signature audit trail event.
// Creates audit trial in History collection: await History.create({ campaignId: candidate.campaignId, candidateName: candidate.name, candidateEmail: candidate.email, status: 'Accepted' });
Phase 4: Real-Time Sync via Server-Sent Events (SSE)
Bina page refresh kiye dashboard status update karne ke liye SSE channel use kiya gaya hai.
  • Backend holds connections in the active sseClients collection.
  • On any status update, server broadcasts updates to frontend clients.
  • React client listener catches SSE push notifications and refreshes state variables dynamically.
