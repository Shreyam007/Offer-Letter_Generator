1. Abstract

OfferFlow HR is a web application designed to automate and optimize the candidate onboarding process for HR coordinators. The platform allows organizations to upload candidate data spreadsheets, perform verification and inline edits, dynamically customize layout templates (Modern, Classic, Minimal), and dispatch personalized PDF/HTML offer letters.

Crucially, the system features a real-time email open tracking engine that updates candidate statuses to "Opened" with exact timestamps the moment a candidate views their offer in an email client. This platform uses the MERN stack (MongoDB, Express, React, Node.js) and leverages Server-Sent Events (SSE) to deliver updates to the client without page refreshes.

2. Introduction & Objectives

Traditional candidate onboarding relies on manual letter generation, individual attachment drafting, and lack of delivery status transparency. The objectives of this project are:

  • Automation: Automate document merging by mapping spreadsheet data directly into pre-styled templates.
  • Data Integrity: Implement spreadsheet-like validation on the client browser before uploading to database resources.
  • Real-time Analytics: Establish a live feedback loop showing email transmission rates, delivery failures, and email opens.
  • Security & Customization: Support encrypted SMTP parameters for separate company entities while allowing rich WYSIWYG letter customization.

3. System Architecture & Workflow

The application follows a decoupled client-server model:

  1. Frontend Client: React SPA compiled using Vite. It handles client-side CSV processing with PapaParse, routes step wizards, and opens a Server-Sent Events (SSE) stream connection when viewing analytics.
  2. Backend API Server: Express.js server executing Node.js. It manages REST endpoints, initiates the Nodemailer mailing loops, generates in-memory buffers, and serves the tracking pixel.
  3. Cloud Database: MongoDB Atlas database managed via Mongoose schemas. Stores company profiles, templates, campaigns, candidates, and delivery audit history.

6. Key Features Implementation Details

A. Interactive Spreadsheet Grid (Data Review)

In Step 2 of the campaign wizard, candidates parsed from the CSV are shown in a grid. HR coordinators can search, filter by role, delete rows, or double-click to edit data fields inline. The frontend saves edits on blur via PUT /api/campaigns/candidates/:id, which triggers dynamic re-validation of email structures and database commits.

B. Dynamic PDF Layout Scaling (Template Editor)

In Step 3, the editor provides an A4-proportioned paper sheet. To display it accurately alongside the configuration bar, we use a ResizeObserver in React. It calculates the viewport dimensions of the preview box and applies a CSS scale transform (e.g. transform: scale(0.65)) to fit the page without altering internal line breaks, font ratios, or margins.

C. Real-time Open Tracking (Server-Sent Events)

When campaigns are sent, our email router embeds a tracking pixel: 

<img src="https://offer-letter-generator-whu4.onrender.com/api/email/track/:candidateId.gif" ... />

When the client loads the mail, the request hits the tracking route in email.js. The backend:

  1. Updates the candidate's status to 'Opened' and saves the openedAt timestamp.
  2. Serves a 43-byte transparent tracking GIF with headers that prevent caching: 
    'Cache-Control': 'no-cache, no-store, must-revalidate', 'Pragma': 'no-cache'
  3. Pushes this event to active frontend client pages using an open **Server-Sent Events (SSE)** channel (GET /track/events). The client updates the status instantly.
  4. If the SSE stream fails, a fallback polling hook automatically fetches the database every 3 seconds using a cache-busting timestamp (?t=Date.now()).

D. Gmail-Safe Pixel Injection (Anti-Clipping)

Gmail clips emails exceeding 102KB. Since our emails embed base64 company logos (e.g. the 136KB AICTE stamp), Gmail automatically hides the bottom sections of emails. Placing the pixel at the bottom would prevent it from loading. We solve this by injecting the tracking pixel immediately after the opening <body> tag at the very top of the email.

E. Persistent Dark Mode

Managed globally via React Context, a class name dark-mode is toggled on the main HTML body tag and cached in local storage. Themes are driven by CSS custom properties in index.css: 

body { --bg-app: #f8fafc; --bg-card: #ffffff; }
body.dark-mode { --bg-app: #0f172a; --bg-card: #1e293b; }

7. Troubleshooting & Layout Refactorings

  • Scrollable Editor Area: Initially, a fixed vertical height constraint and overflow: hidden clipped the editor text area on small screens. We removed the fixed height on the parent view and added a dynamic height: calc(100vh - 280px) with a min-height: 650px rule, restoring clean page scrolling.
  • Logo Bleed-out Overrides: Custom SVG definitions uploaded as company logos bled out of layout containers. We introduced .logo-svg-wrapper wrappers to scale logos to a maximum of 32x32px within navigation toolbars.

8. Conclusion & Future Scope

OfferFlow HR successfully automates document merging and email tracking, providing an easy-to-use platform for HR teams. Future scope includes adding support for SMS/WhatsApp offer alerts, integration with applicant tracking systems (like Greenhouse or Workday), and multi-stage signature signing (DocuSign integrations).
