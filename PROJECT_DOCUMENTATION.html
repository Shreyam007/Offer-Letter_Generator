1. Abstract

OnboardGo is a web application designed to automate and optimize the candidate onboarding process for HR coordinators. The platform allows organizations to upload candidate data spreadsheets, perform verification and inline edits, dynamically customize layout templates (Modern, Classic, Minimal), and dispatch personalized PDF/HTML offer letters.

The application incorporates a real-time status tracking engine that registers open events and timestamps using both a transparent tracking pixel in sent emails and a dedicated Candidate Interactive Portal. It updates candidate status logs in the History drawer immediately without page reloads using Server-Sent Events (SSE).

2. Introduction & Objectives

Traditional candidate onboarding relies on manual template construction, individual mailing, and lack of status transparency. The objectives of this project are:

  • Automation: Automate document merging by mapping spreadsheet data directly into pre-styled templates.
  • Data Integrity: Implement spreadsheet-like validation on the client browser before uploading to database resources.
  • Real-time Analytics: Establish a live feedback loop showing email transmission rates, delivery failures, and email opens.
  • Security & Customization: Support encrypted SMTP parameters for separate company entities while allowing rich WYSIWYG letter customization.

3. System Architecture & Workflow

The application follows a decoupled client-server model:

  1. Frontend Client: React SPA compiled using Vite. It handles client-side CSV processing with PapaParse, routes step wizards, and opens a Server-Sent Events (SSE) stream connection when viewing analytics.
  2. Backend API Server: Express.js server executing Node.js. It manages REST endpoints, initiates the Nodemailer mailing loops, generates in-memory buffers, and serves the tracking pixel.
  3. Cloud Database: MongoDB Atlas database managed via Mongoose schemas. Stores company profiles, templates, campaigns, candidates, and delivery audit history.

6. Key Features Implementation Details

A. Interactive Spreadsheet Grid (Data Review)

In Step 2 of the campaign wizard, candidates parsed from the CSV are shown in a grid. HR coordinators can search, filter by role, delete rows, or double-click to edit data fields inline. The frontend saves edits on blur via PUT /api/campaigns/candidates/:id, which triggers dynamic re-validation of email structures and database commits.

B. Dynamic PDF Layout Scaling (Template Editor)

In Step 3, the editor provides an A4-proportioned paper sheet. To display it accurately alongside the configuration bar, we use a ResizeObserver in React. It calculates the viewport dimensions of the preview box and applies a CSS scale transform (e.g. transform: scale(0.65)) to fit the page without altering internal line breaks, font ratios, or margins.

C. Real-time Status Tracking & Interactive Candidate Portal (Server-Sent Events)

To ensure tracking is 100% reliable and immune to aggressive caching or blocking by mail proxy servers (e.g., Gmail's proxy, Outlook's proxy), the system employs a hybrid tracking mechanism:

  1. Candidate Interactive Portal: A secure public-facing portal (PublicOfferPortal.jsx) is deployed. When candidates click their unique view link, the portal triggers an API call /api/email/track/:candidateId on mount. This ensures the offer status changes to 'Opened' even if pixel-tracking is blocked.
  2. Tracking Pixel: An invisible pixel image is injected near the top of the HTML email template (Gmail-safe position) that points to /api/email/track/:candidateId.gif.
  3. Dynamic Domain Resolution: Automatically resolves the tracking URL host using the request's origin (req.protocol and req.get('host')), removing the need for hardcoded environment variables.
  4. Robust Route Matching: Backend route matches /api/email/track/:candidateId and automatically strips .gif extensions programmatically to avoid dot-separator routing issues.
  5. CORS Headers: Serves with Access-Control-Allow-Origin: * headers, allowing cross-origin requests from mail proxies and remote portal contexts.
  6. SSE Status Broadcast: Once an open/access event is recorded, the backend updates MongoDB with the Opened status and openedAt timestamp, and immediately broadcasts the update to all active admin dashboards over Server-Sent Events (SSE) for zero-refresh UI sync.
  7. Digital Offer Acceptance: The interactive candidate portal features a one-click digital acceptance button. Clicking this triggers POST /api/email/public/candidate-offer/:candidateId/accept, which transitions the candidate's status to Accepted, stamps the exact date, updates campaign metrics, and triggers a real-time SSE broadcast back to the admin dashboard.

D. Gmail-Safe Pixel Injection (Anti-Clipping)

Gmail clips emails exceeding 102KB. Since our emails embed base64 company logos (e.g. the 136KB AICTE stamp), Gmail automatically hides the bottom sections of emails. Placing the pixel at the bottom would prevent it from loading. We solve this by injecting the tracking pixel immediately after the opening <body> tag at the very top of the email.

E. Persistent Dark Mode

Managed globally via React Context, a class name dark-mode is toggled on the main HTML body tag and cached in local storage. Themes are driven by CSS custom properties in index.css: 

body { --bg-app: #f8fafc; --bg-card: #ffffff; }
body.dark-mode { --bg-app: #0f172a; --bg-card: #1e293b; }

F. Automated PDF Offer Letter Attachments

During the campaign dispatch loop, a matching PDF copy of the candidate's personalized offer letter is automatically generated and attached to the email.

  • Pure-JS Compilation: Built dynamically using pdfkit, bypassing heavy headless chrome requirements that would exceed Render's free tier memory bounds.
  • Style Matching: Correctly maps document colors, brand headers, text margins, double line separators, and tabular grid structures according to the chosen template style (Modern, Classic, Minimal).
  • Dynamic Data Binding: Values are compiled and layout elements dynamically adapt based on candidate parameters. Multi-page flows automatically insert page breaks when contents overflow standard A4 layouts.

I. Dynamic Tab Favicon & Branding Renaming

- Dynamic Favicons: Implemented dynamic browser favicon rendering in the React frontend. Both the admin dashboard (via a useEffect inside AppContext.jsx watching selectedCompany) and the public candidate portal (via PublicOfferPortal.jsx watching offerData) dynamically swap the browser tab's favicon link to match the SVG or raster base64 logo of the active company context.

- Branding Architecture: Renamed all brand assets from "OfferFlow HR" to "OnboardGo", aligning titles, meta descriptions, search tags, headers, and footers across the MERN repository.

7. Troubleshooting & Layout Refactorings

  • Scrollable Editor Area: Initially, a fixed vertical height constraint and overflow: hidden clipped the editor text area on small screens. We removed the fixed height on the parent view and added a dynamic height: calc(100vh - 280px) with a min-height: 650px rule, restoring clean page scrolling.
  • Logo Bleed-out Overrides: Custom SVG definitions uploaded as company logos bled out of layout containers. We introduced .logo-svg-wrapper wrappers to scale logos to a maximum of 32x32px within navigation toolbars.

8. Conclusion & Future Scope

OnboardGo successfully automates document merging and email tracking, providing an easy-to-use platform for HR teams. Future scope includes adding support for SMS/WhatsApp offer alerts, integration with applicant tracking systems (like Greenhouse or Workday), and multi-stage signature signing (DocuSign integrations).
